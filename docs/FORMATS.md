# Format coverage

Tapirscan supports the linear and 2D formats listed below. The common group
(EAN13, UPCA, EAN8, UPCE, Code128, Code39, ITF, QRCode and DataMatrix) is the default selection. A scanner's formats are
chosen at creation, and every binding can override them for a single call
without changing the scanner. Python and JavaScript accept the presets below as
strings, a single identifier, or explicit lists; native bindings use the
constants listed here.

is included in that keyword group; — means it is not included, not unsupported.
`common` is the default.

`Code32`, `PZN`, `MSIPlessey`, `Industrial25`, `Pharmacode`, `Code39Extended`, `IATA25` and
`Matrix25` require explicit selection; no group includes them, even `all`.
`Code32`, `PZN` and `Code39Extended` read Code 39 symbols another way, and the
others have no check character or only a weak one, so other bars and noise can
read as them.

Native names follow each language: Rust `Formats::COMMON_1D`, C
`TAPIRSCAN_FORMATS_COMMON_1D`, C++ `Formats::common_1d()` and Java
`Format.COMMON_1D`, with the same pattern for the other presets.

Retail covers the EAN/UPC family, not every format used in retail (for example,
DataBar needs an explicit selection or `"1D"`). Common is a convenience
selection, not a coverage or accuracy guarantee.

EAN13 and UPCA share the primary scan; selecting UPCA adds output normalization,
not another image scan. Enabling more formats can add reader work. JavaScript
loads one complete WASM scanner for the selected effort mode, not a separate
module per format. Reuse a scanner across frames to amortize initialization.

### Pharmacy numbers in Code 39 (Code32, PZN)

Italian Code 32 and German PZN codes are ordinary Code 39 symbols; `Code39`
reads them as raw content (`0CSSBD`, `-02532876`). Select `Code32` and/or `PZN`
to get the pharmacy number instead: `012345676` (the printed `A` prefix is not
part of it) and `02532876`. Only reads with a valid check digit are converted;
the raw Code 39 text stays in the payload bytes. Other Code 39 reads are returned
only if `Code39` is selected too; otherwise they, like unread Code 39 symbols,
are inspection's undecoded regions with the selected format (unknown when both
are selected), never `Code39`.

Both formats are opt-in, because an arbitrary six-character Code 39 passes the
Code 32 check about one time in ten: select them only where these codes are
expected.

### Extended Code 39 (Code39Extended)

Extended (full-ASCII) Code 39 writes the characters plain Code 39 lacks as pairs
of a shift character and a letter: `+H+I` is `hi`, `$I` a tab, `/A` `!`, `%V`
`@`. `Code39` returns the symbol's characters (`+H+I`); select `Code39Extended`
to get the expanded text (`hi`), with the raw Code 39 text in the payload bytes.
Reads whose shift characters do not form valid pairs stay Code 39 reads when
`Code39` is selected, and are otherwise undecoded regions of `Code39Extended`. When `Code39`
is selected too, reads without shift characters are reported as `Code39`, so
only symbols that use full ASCII become `Code39Extended`. The symbology itself
does not mark Extended Code 39, which is why it is opt-in: plain Code 39 data
such as `A+B` would otherwise change meaning.

### MSI Plessey

MSI Plessey has no per-character check, so it is read only when it ends in a
mod-10 (Luhn) check digit, which is returned with the data: `1234566` for
`123456`. Mod-1010 symbols read the same way; symbols with only a mod-11 check
or none are not read. The symbol also needs:

- quiet zones of at least eight modules on both sides, so a symbol cut by the
  image edge is not read;
- at least four digits, including the check digit;
- consistent bar widths across the symbol.

`MSIPlessey` is opt-in.

### Industrial 2 of 5

Industrial 2 of 5, also called Standard 2 of 5 or Code 2 of 5 Industrial (Zint
`C25IND`, Quagga2 `2of5`), stores digits in the bars only: five bars per digit,
two of them wide, with narrow spaces, between a wide-wide-narrow start and a
wide-narrow-wide stop. It is neither ITF nor Matrix 2 of 5 (which Zint 2.16 calls
Standard 2 of 5). The symbology has no
mandatory check digit, so the digits are returned as printed, including a check
digit if the symbol has one. A read needs:

- quiet zones of at least seven narrow modules on both sides, so a symbol cut by
  the image edge is not read;
- one narrow and one wide bar width and one space width across the symbol.

`Industrial25` is opt-in.

### IATA 2 of 5 and Matrix 2 of 5

Both use the same five-element digit patterns with two wide elements, with their
own start and stop, and no mandatory check digit (digits are returned as printed):

- IATA 2 of 5 (`IATA25`, Zint `C25IATA`), used on airline baggage tags, encodes
  digits in the bars only like Industrial 2 of 5, between a start of two narrow
  bars and a stop of a wide and a narrow bar.
- Matrix 2 of 5 (`Matrix25`; Zint 2.16 calls it Standard 2 of 5, `C25STANDARD`)
  encodes each digit in three bars and two spaces, followed by a narrow space,
  between a four-module start bar with five narrow elements and a four-module
  stop bar with four narrow elements.

A read needs quiet zones of at least seven narrow modules on both sides and one
narrow and one wide element width across the symbol (after removing ink spread).
Both formats are opt-in; their symbols are never reported as another 2 of 5
variant.

### Pharmacode

Pharmacode (Laetus, one track) is 2 to 16 narrow or wide bars with equal
spaces; read from the right, a narrow bar is worth 2^i and a wide bar 2^(i+1),
so the symbology encodes 3 to 131070. Values are returned as decimal text. The
symbol has no start, stop or check, so the reader is strict and reads values 32
to 131069:

- at least five bars, and both bar widths present: symbols of only narrow bars
  (values 2^n − 1) or only wide bars (2^(n+1) − 2) are not read, since nothing
  tells the two apart;
- one narrow and one wide bar width and one space width across the symbol, with
  spaces wider than the narrow bars (nominally 1 mm and 0.5 mm), unlike text
  strokes and Industrial 2 of 5;
- quiet zones of at least five space widths on both sides, shown in full by the
  image (a symbol cut by the edge is not read);
- a bar sequence that is a complete Industrial 2 of 5 symbol is left to that format.

The value depends on the reading direction, which the symbol does not show, so
the image defines it: bars are read left to right, and top to bottom in steep
symbols (the switch lies at 45 degrees, where the bars run from bottom left to
top right). A symbol upside down in the image gives the mirrored value. Two-track
Pharmacode is not read. `Pharmacode` is opt-in; select it only where these codes
are expected.

### ITF

Interleaved 2 of 5 has no check of its own (ITF-14 check digits are returned as
data), so a read needs quiet zones and one narrow/wide model across the symbol:
a stain may move a few bars, but a symbol cut by a crop or the image edge must fit
the model exactly. Runs of another symbol, such as a cut Code 39 symbol whose
nine-element characters fill an ITF digit pair, are not read as ITF; where the
same bars form better-fitting Code 39 characters or a Code 39 read, Code 39 wins.

## Effort levels

Effort levels select the following bounded searches:

| Reader        | Low | Medium | High | Very High |
| ------------- | --- | ------ | ---- | --------- |
| Common-linear | 0   | 1      | 2    | 2         |
| QR Code       | 0   | 1      | 2    | 3         |

These are internal reader effort levels, not comparable work or confidence scores.

- **Linear formats:** on frames whose long side exceeds 1536 pixels, High also
  localizes non-retail linear formats on a half-scale raster and Very High on
  overlapping 1536-pixel windows. Low and Medium localize on a 768-pixel raster
  only; for small codes in large photos, crop around them.
- **QR Code:** every mode retries tiny unread images (up to 300 pixels) on an
  enlarged copy. Medium adds gray resampling for grids that fail to decode, a
  block-threshold pass where a QR candidate stayed unread, and retries of large
  frames at 960 and 1280 pixels. High adds threshold/sharpen recovery, block
  thresholds on every unread frame and Reed-Solomon erasures for uncertain
  modules; Very High also tries curved-grid recovery for version 2 and above.
  When QR shares the scan with other formats, the threshold/sharpen and
  equalized/inverted retries run on frames above 262,144 pixels only where a QR
  candidate stayed unread, and the High and Very High reduced copies of large
  frames only on underexposed frames or where a low-resolution copy shows a
  large square area of module-like texture. EAN13-only scans run none of this.
- **Data Matrix:** candidates that do not decode are retried with a wider
  side-ratio window, a grayscale corner refinement and a resampled crop, with
  twice the tries in High. Medium and above add a grid-recovery pass; High and
  Very High also retry unread frames on reduced copies, which reads large blurred
  close-ups. With other formats selected, High tries its finer copy of a frame
  between 262,144 and 8 million pixels only after the coarse copy left a Data
  Matrix candidate.
- **Aztec:** Medium and above add a grid-recovery pass and retry small symbols on
  an enlarged window; Low uses smaller refinement budgets.
- **PDF417:** High and Very High re-read localized symbols that the row reader
  cannot finish by matching blurred codeword templates.
- **MaxiCode:** Medium and above retry large unread frames (over 1920 pixels)
  on reduced copies.
- **Crop retries:** Medium and above retry found-but-unread QR, Micro QR, Data
  Matrix and Aztec symbols on a crop of their region; MaxiCode from High. A Data
  Matrix candidate whose border almost passes is retried after the other regions,
  with Medium's detector limits, searching only the dark-on-light thresholds (its
  nested crops search all four): in Medium on one sharpened crop per frame, from
  High on every crop copy.

When EAN13 and UPCA are both enabled, zero-prefixed EAN13 is returned as UPCA.

Polygons are in input-image coordinates. Metadata such as GS1, reader
initialization and structured append is available directly on Python/JavaScript
barcodes and retained in raw JSON. Structured-append
indices are one-based; symbols are not automatically assembled across frames.
Initialization payloads are data and never executed as configuration.
Non-character/general-purpose ECI is not interpreted as text. Source images
with multiple symbols remain multiple results; single-result selection happens
after scanning and ranks by support.

Undecoded localization for Code39, ITF, Codabar and failed DataBar payloads is
incomplete. Candidate, retry and parsing caps bound the search,
which may still return valid reads. Fixed sampling strategies and
unsupported format variants are not completeness guarantees. Scores are not calibrated probabilities.

Every binding optionally reads two- and five-digit EAN/UPC supplements through
the creation policy `ignore` (default), `read` or `require` (`Ignore`, `Read`,
`Require` in native bindings). EAN8 supplements are a nonstandard extension.
With `read`, every format, including the main EAN/UPC values, reads exactly as
with `ignore`; `require` also drops EAN/UPC reads without a readable supplement.
A supplement must start 4.5 to 16 modules after the main symbol's last bar and
needs about 3.5 bar-free modules after it (or the edge of the label). A
two-digit supplement followed by a separator bar, such as a five-digit one cut
by the image border, is not reported.
